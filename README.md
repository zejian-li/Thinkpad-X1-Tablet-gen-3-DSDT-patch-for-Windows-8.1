# ThinkPad X1 Tablet Gen 3 — Windows 8.1 Physical Button Fix via ACPI DSDT Override

(Report generated by GPT 5.6-Sol after it fixed my tablet buttons under Windows 8.1)

## 1. Scope

This fix applies to a ThinkPad X1 Tablet Gen 3 running Windows 8.1 where the physical side buttons do not work correctly:

* Power
* Volume Up
* Volume Down

The hardware itself is functional, and no replacement button drivers are required. The final working configuration uses the **stock Windows 8.1 Intel HID Event Filter and Intel Virtual Buttons drivers**.

The problem is in the firmware's ACPI routing logic rather than in the drivers.

---

# 2. Root cause

The tablet's firmware uses ACPI to decide how physical button events should be presented to Windows.

Two relevant ACPI devices exist:

```text
INT33D5
Intel HID Event Filter
ACPI object: HIDD
```

and

```text
INT33D6
Intel Virtual Buttons
ACPI object: VGBI
```

The DSDT also distinguishes Windows versions using the `OSYS` value.

For the relevant systems:

```text
Windows 8.1 → OSYS = 0x07DD
Windows 10  → OSYS = 0x07DF
```

The physical power-button handler contains a Windows-10-only condition:

```asl
If (((OSYS >= 0x07DF) && \_SB.HIDD.BTLD))
{
    Notify (\_SB.HIDD, 0xCE)
}
Else
{
    // legacy path
}
```

The release event uses `0xCF`. 

Therefore under Windows 8.1:

```text
OSYS = 07DD

07DD >= 07DF
      ↓
    false
```

and the physical power button is **not routed to Intel HID Event Filter**, despite the `INT33D5` device itself being present and usable.

The `HIDD` device is explicitly available from `OSYS >= 0x07DD`, so there is no fundamental reason it cannot operate under Windows 8.1. 

The volume-button routines have a similar Windows-10-only HIDD path:

```asl
_Q6C → HIDD 0xC4   Volume Up press
_Q6D → HIDD 0xC5   Volume Up release

_Q6E → HIDD 0xC6   Volume Down press
_Q6F → HIDD 0xC7   Volume Down release
```

and they also contain an older `VLBP` routing branch. 

However, Windows 8.1 does not correctly handle these volume events through the HIDD route on this machine.

The firmware already contains a Windows-8-era Virtual Buttons device, `VGBI / INT33D6`, which is enabled starting at `OSYS >= 0x07DD`. 

More importantly, Lenovo's own DSDT already contains another method that sends exactly the same volume notification numbers through `VGBI`:

```asl
Notify (^VGBI, 0xC4)
Notify (^VGBI, 0xC5)

Notify (^VGBI, 0xC6)
Notify (^VGBI, 0xC7)
```



That gives the appropriate Windows 8.1 routing.

# 3. Final working architecture

The final fix uses a hybrid of the two firmware button architectures:

```text
                     Physical buttons
                           │
              ┌────────────┴────────────┐
              │                         │
            Power                    Volume ±
              │                         │
        EC _Q28/_Q29        EC _Q6C/_Q6D/_Q6E/_Q6F
              │                         │
             HIDD                      VGBI
              │                         │
          INT33D5                   INT33D6
              │                         │
   Intel HID Event Filter     Intel Virtual Buttons
              │                         │
        Sleep / Wake             Volume control
```

This works with the **stock Windows 8.1 drivers**.

No driver replacement or backport is required.

# 4. What the DSDT patch changes

The final known-good patch is:

[Download the final DSDT patch](sandbox:/mnt/data/dsdt_final_rev6_power_hidd_volume_vgbi.aml)

It is based directly on Lenovo's original compiled DSDT AML.

Original firmware DSDT size:

```text
182,625 bytes
```

Final patched DSDT size:

```text
182,625 bytes
```

The table is **not decompiled and recompiled**. The original AML byte layout is preserved, with only targeted byte-level changes and a recalculated ACPI checksum.

This is important because recompiling the full Lenovo DSDT can alter substantial amounts of AML even when only a few source lines are edited.

### Power button

For:

```text
_Q28  Power press
_Q29  Power release
```

the condition:

```asl
OSYS >= 0x07DF
```

is changed to:

```asl
OSYS >= 0x07DD
```

This allows Windows 8.1 to use the existing HIDD notifications:

```text
0xCE  Power press
0xCF  Power release
```

through `INT33D5`.

### Volume buttons

The final working patch routes:

```text
_Q6C  Volume Up press
_Q6D  Volume Up release

_Q6E  Volume Down press
_Q6F  Volume Down release
```

to:

```text
VGBI / INT33D6
```

instead of `HIDD / INT33D5`.

Thus:

```text
Volume Up:
C4 / C5 → VGBI

Volume Down:
C6 / C7 → VGBI
```

The final patch also bypasses the old `VLBP` diversion in these four physical volume-button handlers so that the intended VGBI route is taken consistently.

### OEM revision

The patched table uses:

```text
OEM Revision = 6
```

so that Windows selects it in preference to the firmware DSDT and any earlier test revisions.

The ACPI checksum is recalculated after all edits.

# 5. Required Windows configuration

The fix uses Microsoft's ACPI table override mechanism.

It does **not** flash or modify the BIOS.

The patched DSDT is stored in the Windows registry and loaded only by that Windows installation.

Windows must have test signing enabled:

```cmd
bcdedit /set testsigning on
```

Then reboot if it was not already enabled.

Secure Boot must also allow test-signing mode.

---

# 6. Required tool

Use Microsoft's `asl.exe`, supplied with the Windows Driver Kit.

This is different from ACPICA's `iasl.exe`.

`iasl.exe` is useful for ACPI disassembly and analysis, but Microsoft's `asl.exe` provides the Windows registry table-loading mechanism required here.

For example:

```text
C:\ASL\asl.exe
```

# 7. Installing the patched DSDT

Copy:

```text
dsdt_final_rev6_power_hidd_volume_vgbi.aml
```

to a convenient directory, for example:

```text
C:\ACPIDUMP\
```

Open an **elevated Command Prompt** and run:

```cmd
C:\ASL\asl.exe /loadtable -v C:\ACPIDUMP\dsdt_final_rev6_power_hidd_volume_vgbi.aml
```

The output should identify:

```text
OEM id.......: LENOVO
OEM Table id.: SKL
OEM revision.: 00000006
```

and finish with:

```text
Table overloading succeeded.
```

The override will be stored approximately under:

```text
HKLM\SYSTEM\CurrentControlSet\Services\ACPI\Parameters\DSDT\
    LENOVO\
        SKL_____\
            00000006
```

Reboot Windows 8.1.

# 9. Why this solution works

The important point is that the button hardware and Windows 8.1 drivers were never fundamentally broken.

The problem was:

```text
physical button
      ↓
embedded controller
      ↓
ACPI firmware
      ↓
wrong/incompatible OS-specific route
      ↓
Windows never receives the event correctly
```

The patch changes only the final ACPI routing:

```text
Power
→ route to HIDD / INT33D5

Volume
→ route to VGBI / INT33D6
```

This lets the stock Windows 8.1 drivers receive the events in forms they already understand.

---

# 10. Why not simply make the firmware think Windows 8.1 is Windows 10?

A global OS spoof would potentially change many unrelated firmware decisions.

For example, globally forcing:

```text
OSYS = 0x07DF
```

could affect:

* power management;
* graphics;
* docking;
* sensors;
* PCI devices;
* sleep behavior;
* other platform-specific ACPI methods.

The final patch therefore leaves the real Windows 8.1 OS identification intact and changes **only the physical-button routing logic**.

That makes the modification much more targeted.

---

# 11. Why the AML should be patched directly

A full DSDT decompile/edit/recompile cycle is not recommended for this particular firmware.

Even a source file that recompiles with:

```text
0 Errors
```

may generate AML that differs substantially from Lenovo's original firmware implementation.

The safe strategy used here is:

```text
Original Lenovo dsdt.dat
          ↓
preserve original AML
          ↓
modify only specific encoded instructions
          ↓
update OEM revision
          ↓
recalculate ACPI checksum
          ↓
load through Microsoft ASL override
```

Thus essentially all Lenovo firmware AML remains byte-for-byte unchanged.

# 12. Recovery

Because this is a Windows registry override rather than a BIOS modification, an unbootable test table can be removed from another Windows installation.

For example, assuming Windows 8.1 is mounted as `D:`:

```cmd
reg load HKLM\W81REC D:\Windows\System32\Config\SYSTEM
```

Inspect the relevant control set if necessary, then delete the offending DSDT revision:

```cmd
reg delete "HKLM\W81REC\ControlSet001\Services\ACPI\Parameters\DSDT\LENOVO\SKL_____\00000006" /f
```

Then:

```cmd
reg unload HKLM\W81REC
```

After rebooting Windows 8.1, it will fall back to the next lower override revision or ultimately the original firmware DSDT.

For long-term use, keeping only the known-good revision `00000006` is sufficient.

# 14. Concise technical summary

**Problem:** Physical Power, Volume Up and Volume Down buttons do not function correctly on the ThinkPad X1 Tablet Gen 3 under Windows 8.1.

**Cause:** Lenovo's DSDT changes physical-button routing according to the detected Windows generation. The modern HIDD/INT33D5 button path is gated behind `OSYS >= 0x07DF` (Windows 10), while Windows 8.1 reports `0x07DD`. The legacy routing does not provide a usable physical-button implementation on this platform.

**Driver issue:** None. The stock Windows 8.1 Intel HID Event Filter and Intel Virtual Buttons drivers are sufficient.

**Fix:** Use a Windows ACPI DSDT registry override based on Lenovo's original AML:

```text
Power:
_Q28/_Q29
→ enable HIDD route at OSYS >= 0x07DD
→ INT33D5

Volume:
_Q6C/_Q6D/_Q6E/_Q6F
→ route C4/C5/C6/C7 to VGBI
→ INT33D6
```

**Result:**

```text
✓ Power sleep
✓ Power wake
✓ Volume Up
✓ Volume Down
```

No BIOS flashing, global Windows-version spoofing, or non-stock button drivers are required.
